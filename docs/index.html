Conector Darktrace — Guía de configuración

Última actualización: octubre 2026

¿Qué es y para qué sirve?

El conector Darktrace permite que el agente de Ruvic consulte las detecciones de amenazas de tu red: modelos, alertas (model breaches) e incidentes de Cyber AI Analyst, y reconozca alertas ya revisadas. Puedes pedirle cosas como:

  • "¿Qué alertas de Darktrace con puntaje mayor a 0.8 hubo en las últimas 12 horas?"
  • "Resúmeme los incidentes de AI Analyst de esta semana."
  • "Reconoce la alerta 4521, ya la revisamos."

Operaciones soportadas:

OperaciónQué hace
models.listLista los modelos de detección y si están activos
alerts.listObtiene model breaches por ventana de tiempo y puntaje mínimo
incidents.listConsulta incidentes de Cyber AI Analyst
alerts.acknowledgeMarca una alerta como reconocida (escribe)
Reconocer una alerta cambia lo que ve tu equipo Las consultas son de solo lectura. Reconocer una alerta la marca como revisada en Darktrace para todo el equipo de seguridad.

Prerrequisitos

  • Un appliance de Darktrace o una instancia cloud con la API habilitada.
  • Un usuario con permiso de configuración del sistema para crear tokens de API.
  • Conectividad HTTPS desde la plataforma Ruvic hasta el appliance.
  • Reloj sincronizado: la firma incluye la fecha y Darktrace rechaza diferencias grandes.

Configuración en el fabricante

Vas a crear un par de tokens de API (público y privado) en el Threat Visualizer.

  1. Abre la configuración de tokens.

    En el Threat Visualizer ve a System Config → Settings → API Token y pulsa New.

    [ Captura: creación del token de API en System Config — reemplazar por assets/img/darktrace-token.png ]
  2. Limita los permisos.

    Asocia el token a un usuario o rol con lectura de model breaches, modelos y Cyber AI Analyst, más reconocer breaches. Evita permisos de administración.

  3. Copia ambos tokens.

    Guarda el token público y el token privado. El privado solo se muestra una vez.

Permisos requeridos

Principio de mínimo privilegio: el par de tokens solo necesita lo siguiente.

PermisoPara qué lo usa el conector
Model breaches (lectura)Obtener alertas con get_alerts
Models (lectura)Listar modelos con list_models
Cyber AI Analyst (lectura)Consultar incidentes con list_incidents
Acknowledge breachesReconocer alertas con acknowledge_alert

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Darktrace y pulsa Configurar. Diligencia el formulario con los valores de la sección anterior:

Campo del formularioValor
URL del appliance de DarktraceURL del Threat Visualizer o de la instancia cloud, ej. https://darktrace.miempresa.com
Token públicoToken público del par creado
Token privadoToken privado. Se guarda cifrado y no se vuelve a mostrar
Verificar certificado SSLActívalo siempre, salvo appliances con certificado autofirmado en redes de confianza
Timeout de conexión (segundos)Opcional; 15 segundos por defecto

Guarda y pulsa Probar conexión: la plataforma valida las credenciales y el acceso.

[ Captura: formulario del conector Darktrace en Settings → Conectores — reemplazar por assets/img/darktrace-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder con éxito y la tarjeta debe quedar en estado Configurado.

  2. Prueba mínima con el agente.

    Abre una conversación nueva y pídele:

    "¿Cuántas alertas de Darktrace con puntaje mayor a 0.5 hubo hoy?"

    El agente debe responder con alertas reales del appliance. No le pidas reconocer alertas durante la prueba.

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Tokens de API inválidos"El token público o el privado están mal copiados, o el par fue eliminado. Crea uno nuevo.
"Darktrace rechazó la fecha de la firma"El reloj del runtime y el del appliance difieren. Sincroniza NTP en el appliance.
"Los tokens no tienen permiso"Darktrace redirigió a /403: amplía los permisos del usuario o rol del token.
"Error de certificado SSL"El appliance usa un certificado autofirmado. Instala uno válido o desactiva la verificación en una red de confianza.

Preguntas frecuentes y notas de seguridad

¿El agente puede cambiar modelos o bloquear tráfico?

No. Solo consulta y reconoce alertas. No toca modelos, respuestas autónomas (RESPOND) ni configuración.

¿Qué hago si el token privado se filtra?

Elimina el par en System Config → API Token, crea uno nuevo y actualízalo en el formulario.

¿Dónde quedan guardados los tokens?

Como secretos cifrados en la plataforma. La interfaz no vuelve a mostrarlos.
